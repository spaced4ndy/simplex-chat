# Plan: a received Markdown file in the app's file viewer

Tapping a received `.md` file opens it in the app's viewer, in its "Formatted" view: headings, bold text, lists, links and tables drawn as such. A button in the viewer's top bar, "Text view", switches to the file's text as written; the same button, then "Formatted view", switches back. The viewer remembers the view last chosen, so always return it to the Formatted view before closing it. Close the viewer with `ui key BACK`.

A peer, alice, sends the files. These cases record how this app draws them, for a reviewer who compares them with another app's rendering of the same files: take every shot the plan names, with the viewer fully open and nothing covering it, and describe what shows. For each `ui find` the plan names, quote its output.

| ID | Do | Expect |
|---|---|---|
| M1 | `peer alice link`, then `ui open-link '<the link it printed>'`. In the app, confirm connecting ("Connect", or "Open new chat" and then the chat's connect button). `peer alice wait 30`. `peer alice chats` shows the app's profile name as alice sees it: use it as `@<name>` in the commands below (quoted, as in `'@citester'`). `ui shot M1-connected`. | The app shows the chat with alice, connected. |
| M2 | `peer alice file '@<name>' README.md`. In the app, in alice's chat, the message with the file "README.md" shows; if it offers to download, tap it and wait until the file is received. Tap the file: the viewer opens. `ui shot M2-readme-top`. `ui find "Welcome to SimpleX Chat"` and `ui find "## Welcome"`. Scroll down with `ui scroll 540 1500 down` twice, `ui shot M2-readme-scrolled`. Scroll down four more times, `ui shot M2-readme-further`. | Describe what shows: which parts are formatted (headings, bold, lists, links, the table) and whether any Markdown markers or HTML tags show as text, and where. |
| M3 | Tap "Text view". `ui shot M3-readme-text`. Tap "Formatted view". `ui shot M3-readme-formatted-again`. `ui key BACK`. | The Text view shows the file's text as written; the Formatted view comes back as in M2. |
| M4 | `peer alice text-file '@<name>' void-tag.md '# Before the tag' ' ' '<img src="logo.png" width="100">' ' ' '## After the tag' ' ' 'Some **bold** text and a [link](https://simplex.chat).' ' ' '- one' '- two'`. Open it as in M2. `ui shot M4-void-tag`. `ui find "After the tag"` and `ui find "## After"`. `ui key BACK`. | Describe what shows, line by line, including what shows where the `<img …>` line is. |
| M5 | `peer alice text-file '@<name>' inline-tag.md '# Inline tag' ' ' 'A line with a break<br>in the middle.' ' ' '## After the paragraph' ' ' 'Some **bold** text.'`. Open it. `ui shot M5-inline-tag`. `ui find "After the paragraph"` and `ui find "## After"`. `ui key BACK`. | Describe what shows, including what shows for `<br>`. |
| M6 | `peer alice text-file '@<name>' closed-tag.md '# Closed tag' ' ' '<a href="https://simplex.chat">SimpleX</a>' ' ' '## After the tag' ' ' 'Some **bold** text.'`. Open it. `ui shot M6-closed-tag`. `ui find "After the tag"` and `ui find "## After"`. `ui key BACK`. | Describe what shows, including what shows for the `<a …>…</a>` line. |

Record a case ok when its shots are taken and its description is in the record; these cases compare renderings, so none of them is a bug by itself unless the app fails to open the file or shows an error.
